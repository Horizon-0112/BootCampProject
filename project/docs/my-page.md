# 마이페이지

기존 프로필 카드·탭·모바일 CSS를 사용하며 화면은 `/my-page`에서 제공한다.
로그인하지 않은 화면 요청은 로그인 페이지로 이동하고, API는 401 JSON을 반환한다.

| 기능 | 요청 |
|---|---|
| 내 정보와 활동 수 | GET /api/v1/me |
| 닉네임·비밀번호 수정 | PATCH /api/v1/me |
| 회원 탈퇴 | DELETE /api/v1/me |
| 내가 작성한 레시피 | GET /api/v1/me/recipes |
| 내가 작성한 댓글 | GET /api/v1/me/comments |
| 북마크한 레시피 | GET /api/v1/me/bookmarks |

목록은 `page=0&size=10` 형식으로 조회한다. size는 1~50이며 최신순, 같은 작성일에서는 ID 내림차순이다.
사용자 ID를 요청에서 받지 않고 인증된 세션의 이메일로 본인을 식별한다.
목록은 `items`, `page`, `size`, `total`을 반환하고 화면은 빈 목록·로딩·오류·재시도를 처리한다.
레시피 상세 페이지는 현재 구현되어 있지 않아 제목·설명·작성일을 목록 안에 표시한다.

## 정보 수정

이메일은 로그인 ID로 유지하며 닉네임과 비밀번호를 변경할 수 있다.
JSON 필드: `nickName`, `currentPassword`, `pw`, `pwConfirm`.
현재 비밀번호가 필요하며 새 비밀번호 두 필드를 비우면 닉네임만 변경한다.
닉네임 중복과 비밀번호 형식을 서버에서 검사하고 항목 아래에 오류를 표시한다.
비밀번호 변경 시 기존 재설정 토큰을 삭제하고 이 서버에 등록된 모든 로그인 세션을 만료시킨다.
다중 서버 배포 시에는 공유 세션 저장소가 추가로 필요하다.

## 회원 탈퇴

JSON 필드: `currentPassword`, `confirmed: true`.
화면에 삭제 범위를 안내하고 동의 체크 및 최종 확인 후 요청한다.
계정, 작성 레시피·댓글, 북마크, 냉장고, 재설정 토큰을 삭제한다.
삭제되는 레시피의 재료 연결·조리 단계·다른 회원의 댓글과 북마크도 정리한다.
다른 회원의 계정과 나머지 레시피, 공용 재료 테이블은 유지한다.
모든 삭제는 하나의 트랜잭션이며 외래키 충돌 등이 발생하면 전체 롤백한다.
커밋 성공 후 모든 등록 세션을 만료시키고 현재 세션에서 로그아웃한다.

## DB와 검증

실제 MySQL의 users, recipes, comments, saved_recipes 및 외래키 구조를 확인하여 구현했다.
기존 콘텐츠 테이블은 JdbcTemplate로 조회·삭제하며 회원 변경은 JPA로 처리한다.
이번 기능을 위해 운영 테이블을 추가하거나 변경하지 않는다.

- 전체 JUnit 테스트 16개 통과 (마이페이지 7개).
- 본인 데이터 범위, 페이지 경계, CSRF, 비밀번호 검증, 세션 만료, 탈퇴 데이터 보존 범위 및 롤백 확인.
- 로컬 MySQL + 실제 HTTP에서 내 정보, 값이 있는 세 목록, 닉네임 수정, 탈퇴, 세션 무효화 확인.
- 로컬 검증용 계정과 콘텐츠는 탈퇴 기능으로 정리했다.
- JavaScript 문법 검사 통과. 브라우저 직접 클릭 검증은 수행하지 않았다.

정리한 파일: 미사용 UserLoginDto, sign-up.css, 빈 RecipeIngredientRepositoryTest, 기본 HELP.md 및 임시 진단 파일.
